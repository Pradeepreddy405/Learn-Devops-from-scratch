# Maven Lifecycle – Complete Explanation

## 1. What is Maven?

**Apache Maven** is a Java build automation and dependency management tool used to simplify the software development and build process.

Maven helps developers to:

- Build Java applications.
- Manage external libraries and dependencies.
- Standardize project directory structures.
- Compile Java source code.
- Execute unit tests.
- Package applications into JAR or WAR files.
- Install and distribute build artifacts.
- Integrate with CI/CD pipelines.

**In simple terms:**

`Maven = Build Automation + Dependency Management + Project Standardization`

### What is POM.xml?

POM stands for **Project Object Model**.

`pom.xml` is the main configuration file of a Maven project. It contains information such as:

- Project name and version.
- Group ID and Artifact ID.
- Dependencies.
- Build configurations.
- Maven plugins.
- Repository information.

Example:

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>myapp</artifactId>
    <version>1.0</version>
    <packaging>jar</packaging>

</project>
```

## 2. What is Maven Lifecycle?

A **Maven Lifecycle** is a predefined sequence of build phases that Maven follows to automate the software build process.

These phases perform different operations, such as:

- Validating the project.
- Compiling source code.
- Executing tests.
- Packaging applications.
- Verifying build results.
- Installing artifacts.
- Deploying artifacts to remote repositories.

You do not need to execute every operation manually.

You can execute a single Maven command, and Maven automatically executes all the preceding phases within that lifecycle.

**Example:**

```bash
mvn package
```

Maven automatically executes the required phases before packaging the application.

## 3. Why Do We Need Maven Lifecycle?

### Without Maven Lifecycle

- Manual compilation.
- Manual dependency management.
- Manual testing.
- Inconsistent build processes.
- Difficult integration with CI/CD.
- Increased chances of human errors.

### With Maven Lifecycle

- Standardized build process.
- Automated compilation and testing.
- Centralized dependency management.
- Repeatable builds.
- Easier CI/CD integration.
- Reduced manual effort.

## 4. Maven Has 3 Built-in Lifecycles

Maven provides three built-in lifecycles.

| Lifecycle | Purpose |
|---|---|
| Default | Builds, packages, and distributes applications |
| Clean | Removes files generated by previous builds |
| Site | Generates project documentation and website |

Each lifecycle contains multiple phases.

**Important:** Each lifecycle is independent. Running a phase executes the preceding phases of that same lifecycle, not phases from every lifecycle.

## 5. Default Lifecycle (Most Important)

The Default Lifecycle is the primary lifecycle used to build Java applications.

It contains multiple phases, starting with `validate` and ending with `deploy`.

### Commonly Used Default Lifecycle Phases

```text
1.  validate
2.  compile
3.  test
4.  package
5.  verify
6.  install
7.  deploy
```

These are the seven most commonly discussed phases, not the complete list.

### 1. validate

**Purpose:** Checks whether the project is correct and all necessary information is available to perform the build.

It checks project configuration and build prerequisites.

Command:

```bash
mvn validate
```

### 2. compile

**Purpose:** Compiles Java source code into Java bytecode.

```text
.java  →  .class
```

Source code location:

```text
src/main/java/
```

Compiled output:

```text
target/classes/
```

Command:

```bash
mvn compile
```

### 3. test

**Purpose:** Executes unit tests against the compiled application code.

Maven commonly uses testing frameworks such as:

- JUnit
- TestNG

Test source location:

```text
src/test/java/
```

Compiled test classes:

```text
target/test-classes/
```

Test reports:

```text
target/surefire-reports/
```

Command:

```bash
mvn test
```

**Important:** Maven executes the earlier required phases, including compilation and test compilation, before running unit tests.

### 4. package

**Purpose:** Packages the compiled application into a distributable format.

Depending on the project's packaging configuration, Maven can generate:

- JAR – Java Archive
- WAR – Web Application Archive
- EAR – Enterprise Application Archive

Example:

```xml
<packaging>jar</packaging>
```

Build output:

```text
target/myapp-1.0.jar
```

Command:

```bash
mvn package
```

**Note:** The exact artifact name depends on the project's artifact ID, version, packaging, and plugin configuration.

### 5. verify

**Purpose:** Performs additional checks to verify that the packaged application meets the required quality criteria.

Examples include:

- Integration test verification.
- Code quality checks.
- Build validation.
- Additional verification tasks configured through Maven plugins.

Command:

```bash
mvn verify
```

**Important:** Integration tests and quality checks are not automatically configured in every Maven project. They require appropriate plugin configurations.

### 6. install

**Purpose:** Installs the generated artifact into the local Maven repository.

Default local repository:

```text
~/.m2/repository/
```

Example:

```text
~/.m2/repository/com/example/myapp/1.0/
```

Command:

```bash
mvn install
```

**Use case:**

Other Maven projects on the same machine can use the installed artifact as a dependency without downloading it from a remote repository.

### 7. deploy

**Purpose:** Publishes the generated artifact to a configured remote Maven repository.

Examples of artifact repositories:

- Sonatype Nexus Repository.
- JFrog Artifactory.
- GitHub Packages.
- AWS CodeArtifact.

Command:

```bash
mvn deploy
```

**Use case:**

Share application artifacts with other developers, teams, and CI/CD environments.

**Important:** Maven deploy publishes artifacts to a repository. It does not directly deploy an application to an EC2 instance or Kubernetes cluster.

## 6. Complete Default Lifecycle Phases

Apart from the seven commonly used phases, Maven has additional phases that handle source generation, resource processing, integration testing, and other build operations.

The complete Default Lifecycle phase sequence is:

| Order | Phase | Purpose |
|---|---|---|
| 1 | validate | Validate project configuration |
| 2 | initialize | Initialize build state |
| 3 | generate-sources | Generate source code |
| 4 | process-sources | Process source code |
| 5 | generate-resources | Generate resources |
| 6 | process-resources | Copy and process resources |
| 7 | compile | Compile application source code |
| 8 | process-classes | Process compiled classes |
| 9 | generate-test-sources | Generate test source code |
| 10 | process-test-sources | Process test source code |
| 11 | generate-test-resources | Generate test resources |
| 12 | process-test-resources | Copy and process test resources |
| 13 | test-compile | Compile test source code |
| 14 | process-test-classes | Process compiled test classes |
| 15 | test | Execute unit tests |
| 16 | prepare-package | Prepare for packaging |
| 17 | package | Generate JAR/WAR/EAR |
| 18 | pre-integration-test | Prepare integration test environment |
| 19 | integration-test | Execute integration test activities |
| 20 | post-integration-test | Perform integration test cleanup |
| 21 | verify | Verify build quality |
| 22 | install | Install artifact into local repository |
| 23 | deploy | Publish artifact to remote repository |

**Remember:** Maven executes these phases in sequence up to the requested phase.

## 7. Clean Lifecycle

The Clean Lifecycle is responsible for removing files generated during previous builds.

It contains three phases:

| Phase | Purpose |
|---|---|
| pre-clean | Execute operations before cleaning |
| clean | Remove generated build files |
| post-clean | Execute operations after cleaning |

Command:

```bash
mvn clean
```

Example:

Before cleaning:

```text
myapp/
├── src/
├── pom.xml
└── target/
    ├── classes/
    ├── test-classes/
    └── myapp-1.0.jar
```

After cleaning:

```text
myapp/
├── src/
└── pom.xml
```

**Important:** The `clean` phase normally removes the `target/` directory. It does not delete your original source code or `pom.xml`.

---

## 8. Site Lifecycle

The Site Lifecycle is used to generate and deploy project documentation.

It contains four phases:

| Phase | Purpose |
|---|---|
| pre-site | Execute operations before generating documentation |
| site | Generate project documentation |
| post-site | Execute operations after site generation |
| site-deploy | Publish generated documentation |

Commands:

```bash
mvn site
```

```bash
mvn site-deploy
```

Use case:

Generate technical documentation, project reports, and a project website.

## 9. Important Maven Commands Used in Real Projects

| Command | Purpose |
|---|---|
| `mvn validate` | Validate project configuration |
| `mvn compile` | Compile Java source code |
| `mvn test` | Execute unit tests |
| `mvn package` | Generate JAR/WAR |
| `mvn verify` | Verify build results |
| `mvn install` | Install artifact locally |
| `mvn deploy` | Publish artifact remotely |
| `mvn clean` | Remove generated build files |
| `mvn clean package` | Clean and package application |
| `mvn clean install` | Clean, build, test, package, and install |
| `mvn clean deploy` | Clean, build, test, package, install, and publish |
| `mvn -version` | Display Maven version |
| `mvn dependency:tree` | Display project dependency hierarchy |

## 10. How Maven Lifecycle Works in CI/CD

Consider a real-world scenario.

A developer pushes Java application code to GitHub.

A CI/CD pipeline using Jenkins or GitHub Actions triggers the Maven build.

Example pipeline execution:

```text
Developer
    |
    v
GitHub Repository
    |
    v
Jenkins / GitHub Actions
    |
    v
Maven Build
    |
    v
Validate Project
    |
    v
Compile Source Code
    |
    v
Execute Unit Tests
    |
    v
Package Application
    |
    v
Verify Build
    |
    v
Install / Deploy Artifact
    |
    v
Nexus / Artifactory / CodeArtifact
    |
    v
Application Deployment
    |
    v
EC2 / Kubernetes
```

Example Jenkins build command:

```bash
mvn clean package
```

This command:

1. Removes previously generated build files.
2. Validates the project.
3. Processes application resources.
4. Compiles Java source code.
5. Compiles and executes unit tests.
6. Packages the application into a JAR/WAR.

The generated artifact can then be published to an artifact repository or deployed to an application environment using subsequent CI/CD stages.

## 11. Important Interview Questions

**Q1. What is Maven?**

Maven is a Java build automation and dependency management tool that automates compilation, testing, packaging, and artifact distribution.

**Q2. What is a Maven Lifecycle?**

A Maven Lifecycle is a predefined sequence of phases that automates the software build process.

**Q3. How many built-in lifecycles does Maven have?**

Maven has three built-in lifecycles: Default, Clean, and Site.

**Q4. What happens when you execute `mvn package`?**

Maven executes all preceding phases in the Default Lifecycle before packaging the application into its configured distributable format.

**Q5. What is the difference between `mvn install` and `mvn deploy`?**

- `mvn install` installs the artifact into the local Maven repository.
- `mvn deploy` publishes the artifact to a configured remote Maven repository.

**Q6. What is the difference between `mvn clean` and `mvn clean package`?**

- `mvn clean` removes previously generated build files.
- `mvn clean package` removes previous build files and performs a fresh build up to the package phase.

**Q7. Does `mvn test` generate a JAR file?**

No. It executes the unit tests but does not reach the package phase.

**Q8. What is the difference between a Maven Lifecycle and a Maven Plugin?**

- Lifecycle: Defines the sequence of build phases.
- Plugin: Provides the actual functionality through goals bound to lifecycle phases.

For example:

```text
compile phase
      |
      v
Maven Compiler Plugin
      |
      v
compiler:compile goal
      |
      v
Java source code compiled
```

## 12. Important Things to Remember

- Maven is a build automation and dependency management tool.
- `pom.xml` is the main Maven project configuration file.
- Maven has three built-in lifecycles.
- The Default Lifecycle is the most commonly used lifecycle.
- A lifecycle contains multiple phases.
- Executing a phase automatically executes its preceding phases within the same lifecycle.
- Maven plugins provide the actual functionality through goals.
- `mvn clean package` is commonly used for a fresh application build.
- `mvn install` stores artifacts in the local Maven repository.
- `mvn deploy` publishes artifacts to a remote Maven repository.
